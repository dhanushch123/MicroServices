# Local ELK setup

This setup runs Elasticsearch, Logstash, and Kibana with Docker Compose and reads the Spring Boot rolling log files from the repository's `logs` directory:

```text
logs/
  api-gateway/*.log
  order-service/*.log
  inventory-service/*.log
```

The Compose file mounts that directory read-only into Logstash at `/logs`. Logstash parses the log timestamp, level, thread, trace context, and service name, and indexes events as `spring-logs-YYYY.MM.dd`.

> This Compose setup is for local development. Elasticsearch security is enabled, but its HTTP connection is not configured for TLS.

## 1. Prepare credentials

Run these commands from the repository root in PowerShell. Create a local `.env` file (it is excluded from Git) and open it to edit:

```powershell
Copy-Item elk\.env.example elk\.env
notepad elk\.env
```

Replace the example values with strong passwords. The two variables are:

```dotenv
ELASTIC_PASSWORD='your-elastic-user-password'
KIBANA_SYSTEM_PASSWORD='your-kibana_system-password'
```

Do not commit or share `elk\.env`. Quotes are useful when passwords contain characters that have special meaning in `.env` files.

## 2. Start Elasticsearch

Start Elasticsearch with the configured `ELASTIC_PASSWORD`:

```powershell
docker compose --env-file elk\.env -f elk\docker-compose.yaml up -d elasticsearch
docker compose --env-file elk\.env -f elk\docker-compose.yaml ps
```

For a new Elasticsearch data volume, `ELASTIC_PASSWORD` sets the initial password for the `elastic` user. For an existing volume, changing that Compose variable does **not** change the password already stored in Elasticsearch.

To set or reset passwords on a running container, use the interactive commands below. Update the matching values in `elk\.env` to exactly the passwords entered/generated by these commands:

```powershell
docker exec -it elasticsearch bin/elasticsearch-reset-password -u elastic -i
docker exec -it elasticsearch bin/elasticsearch-reset-password -u kibana_system -i
```

`elastic` is the administrator account used to sign in to Kibana and for Logstash's Elasticsearch output in this local setup. `kibana_system` is a service account used only by Kibana to connect to Elasticsearch; do not use it to sign in to the Kibana UI.

## 3. Start Logstash and Kibana

After the passwords in `.env` match Elasticsearch, start the remaining services:

```powershell
docker compose --env-file elk\.env -f elk\docker-compose.yaml up -d logstash kibana
docker compose --env-file elk\.env -f elk\docker-compose.yaml ps
```

If Logstash or Kibana was already running before changing credentials, recreate it to load the new values:

```powershell
docker compose --env-file elk\.env -f elk\docker-compose.yaml up -d --force-recreate logstash kibana
```

## 4. Check services and view logs

Follow service logs:

```powershell
docker logs -f elasticsearch
docker logs -f logstash
docker logs -f kibana
```

Logstash's `rubydebug` output should show parsed events with a `service` field. Elasticsearch authentication failures or Kibana `unable to authenticate user [kibana_system]` errors usually mean the relevant password in `.env` does not match Elasticsearch; reset that user's password and recreate the affected container.

Open [http://localhost:5601](http://localhost:5601) and sign in as `elastic`. In Kibana, create a data view named `spring-logs-*` and select `@timestamp` as its time field, then use Discover to inspect events. Logs are only ingested from files visible under the mounted `logs` directory.

## Compose services and ports

The configuration is in [`docker-compose.yaml`](docker-compose.yaml), and the file input, parsing, and Elasticsearch output are in [`logstash.conf`](logstash.conf).

| Service | Local URL/port | Purpose |
| --- | --- | --- |
| Elasticsearch | `http://localhost:9200` | Stores and searches indexed logs |
| Kibana | `http://localhost:5601` | UI for searching and visualizing logs |
| Logstash monitoring API | `http://localhost:9600` | Logstash status API |
| Logstash Beats input | `localhost:5044` | Reserved; not used by the current file input |

## Stop the stack

From the repository root:

```powershell
docker compose --env-file elk\.env -f elk\docker-compose.yaml down
```

This stops and removes the containers but preserves the named Elasticsearch data volume. To delete indexed data as well, remove that specific volume only after confirming it is no longer needed:

```powershell
docker volume ls
docker volume rm elk_elasticsearch-data
```

The generated volume name can differ if the Compose project name was customized. Do not remove the volume unless you intend to permanently delete the Elasticsearch data.
